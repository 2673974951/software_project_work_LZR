# 数据集说明

本目录下的三张 CSV 完整描述了一个 RCPSP（资源受限项目调度）实例。
替换为自己的项目数据后，全部代码与脚本可直接运行，无需修改任何代码。

## 1. tasks.csv —— 任务表

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| task_id | 字符串 | 是 | 任务编号，项目内唯一，建议用 T01、T02 形式 |
| name | 字符串 | 是 | 中文任务名称 |
| phase | 字符串 | 否 | 所属阶段，用于甘特图着色；缺省为“未分类” |
| duration | 整数 | 是 | 工期（工作日），必须为正整数 |
| predecessors | 字符串 | 否 | 紧前任务编号，多个用竖线 `|` 分隔；空表示起始任务 |

示例：

```csv
task_id,name,phase,duration,predecessors
T01,项目立项与章程,启动,3,
T02,需求调研与用户访谈,需求,6,T01
T10,设计评审与基线冻结,设计,2,T05|T06|T07|T08|T09
```

## 2. resources.csv —— 角色与容量

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| role_id | 字符串 | 角色编号，如 BE、FE |
| role_name | 字符串 | 中文角色名 |
| capacity | 整数 | 该角色同一时刻最多可并行投入的人数 |

```csv
role_id,role_name,capacity
BE,后端开发,4
FE,前端开发,2
```

## 3. task_resources.csv —— 资源需求矩阵

第一列为 `task_id`，其后每一列对应一个 `role_id`，单元格为该任务在
**整段工期内持续占用**的人数。留空或填 0 表示不占用该角色。

```csv
task_id,PM,BA,ARCH,DBA,UI,BE,FE,QA,SEC,OPS
T13,0,0,0,0,0,2,0,0,0,0
T32,0,0,0,0,0,1,1,2,0,0
```

## 4. 建模假设

本实现遵循 RCPSP 的经典假设：

1. **非抢占**：任务一旦开工必须连续执行到结束，中途不能暂停或换人。
2. **工期固定**：任务工期是确定值，与投入人数无关（不建模“人多力量大”）。
3. **资源需求恒定**：任务执行期间对各角色的占用不变。
4. **可再生资源**：人力在每个工作日结束时“恢复”容量，不跨天累积消耗。
5. **角色内同质**：同一角色下的人可以互相替换，不区分资历。

## 5. 数据校验

代码在载入时强制检查以下条件，任一不满足即抛出带具体任务编号的
`DataError`，避免错误数据静默进入调度：

- 任务编号唯一；
- 工期为正整数；
- 紧前任务必须存在，且不能依赖自身；
- 依赖关系构成的图无环；
- 任一任务对某角色的需求不得超过该角色的容量（否则实例不可行）。

## 6. 关于本案例数据

本案例为“智慧校园综合服务平台 v2.0”，42 个任务、71 条依赖、10 类角色、
20 人团队，是**教学案例数据**：任务划分与工作量比例参考同类校企合作项目
设定，并非某企业的真实工时记录。报告第 6 章对此作为方法局限做了讨论。
